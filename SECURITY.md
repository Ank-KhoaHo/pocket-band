# Security policy

## Reporting a vulnerability

**Report privately**, through GitHub's private advisory form:
<https://github.com/Ank-KhoaHo/pocket-band/security/advisories/new>, or use *Security → Report a vulnerability* on the repository page.
There is no security email address, deliberately — an unmonitored inbox is worse than no inbox.
Please do not open a public issue for a suspected vulnerability — that discloses it to everyone at once, before there is a fix to give them.

Include the version you're on, the shortest input or steps that reproduce it, and what you
expected to happen instead.

### What to expect

This is a small project, so: acknowledgement once the report is seen, and a fix in the next
release once it is confirmed. No fixed response time is promised — one that cannot be honestly
kept is worse than none at all.

## Supported versions

Only the latest released version of pocket-band is supported. There are no maintenance
branches, so a fix ships in the next release rather than being backported.

## Scope

### In scope

- Anything that lets untrusted input make pocket-band do something its documentation says it
  cannot.
- A default configuration that is less safe than what is documented.

### Not findings

These are documented limits, not bugs. A report is welcome only if it shows the real behaviour
is worse than what is already written down.

- A limitation already stated in [README.md](README.md) or [ROADMAP.md](ROADMAP.md).
- Something that requires the attacker to already control the machine running the project, or
  the configuration handed to it.
- A report generated by a scanner with no demonstrated, working impact.

### Out of scope

A vulnerability in a dependency this project uses, rather than in code this project owns —
report that to the dependency's own maintainers.
